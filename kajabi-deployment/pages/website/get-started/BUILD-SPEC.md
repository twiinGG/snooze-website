## Engine requirements (`get-started-engine.js`)

- An IIFE that renders into `<div id="get-started-page"></div>`. It exposes `window.__snoozeGetStarted__` for tests.
- The flow, copy, start-here map, offers and config are inlined by the bundler as `window.SNOOZE_GS_DATA = {flow, copy, startHere, offers, config}`.
- **One question per screen**, Typeform style: large question, optional helper line, option chips (single-select advances on tap after 250ms; multi-select shows a sticky CONTINUE, enabled when `min` is met), and a thin progress bar (brand orange on cream). Back chevron from screen 2. Keyboard: number keys pick options, Enter continues. Focus moves to each new question heading. `prefers-reduced-motion` respected.
- **Branching:** honour `show_if`, `options_from`, `options_by_group` (the group comes from the top-of-mind band, or the only band chosen), `default_if_hidden`, and `exclusive_option` (choosing `none` clears the others, and choosing any other option clears `none`).
- **State:** saved to `localStorage[flow.storage_key]` on every answer as `{v:1, step, answers, started_at, updated_at, email_captured, completed}`. All storage access goes through try/catch; if storage is blocked, the flow still works in memory.
- **Resume:**
  - On load, if the state has `completed:true` or `email_captured:true`, show the plan.
  - Otherwise, if a step is in progress, show a "Pick up where you left off?" screen (copy key `resume.*`) with Continue and Start over.
  - `?r=<token>` restores the answers from a base64url JSON of `{a: answers}` (answer IDs only, never email or name), sets `email_captured:true` and shows the plan. It fires `get_started_resume {via:'email'}`.
  - A resume from the stored state fires `{via:'return'}`.
- **Email screen:** must use the real Kajabi form embed. Per `pages/website/KAJABI-FORM-EMBED-PATTERN.md`: no custom `<form>`, no hand-written inputs, and no `fetch` to Kajabi.
  - Insert `<script src="https://www.joinsnooze.com/forms/{kajabi_form_id}/embed.js">` into the screen container.
  - Wait for the form to render (a MutationObserver with a 6s timeout).
  - Fill the hidden custom fields named in `config.form_field_names` (`age_band`, `primary_struggle`, `help_style`, `start_here_title`, `start_here_url`, `resume_token`) and hide their wrappers.
  - On the form's `submit` event, save `email_captured:true` and push the events. Do **not** preventDefault; Kajabi owns the POST and redirect.
  - The form's after-submit redirect is set in Kajabi to `/get-started` (Kade setup step), so the page reloads, finds `email_captured:true` and shows the plan.
  - If the embed fails to render within 6s, show copy key `email.fallback` with a "See my plan without saving" link. This is honest: nothing is claimed as saved.
  - Also POST the answers to `config.n8n_webhook_url` with `navigator.sendBeacon` (payload: `source:'get_started'`, answers, UTMs from the existing first/current-touch storage, `currency_preference`), skipped if the URL is empty. This goes to n8n analytics, not to Kajabi capture, so the embed rule does not apply.
- **Plan screen:** see "Plan rendering".
- **Events:** push to `window.dataLayer` using the names in `flow.events`. `get_started_step` carries `{step_id, step_index}`. `get_started_plan_viewed` carries `{help_style, highlighted_option, safety_route:boolean}`. `get_started_safety_route` carries no answer detail. `get_started_option_click` carries `{offer}`. Never push email, name or free text.
- **Kill switch:** if `config.enabled === false`, render a single link to `/one-on-one-sleep-consultations` and `/snooze-membership`, and nothing else.

## Plan rendering

The plan is built from `plan_layout`, `copy.json`, `start-here-map.json` and `offers.json`:

1. Header (copy `plan.header`, `plan.prepared_by`) with Sally's photo (`copy.plan.photo_url`).
2. Reflection: `plan.reflection.<age_group>` and `plan.reflection_struggle.<struggle_id>`, where `{age_label}` and `{struggle_label}` are interpolated.
3. Tabs *For your baby / For you*:
   - **Right now:** the start-here item for (group, primary_struggle). Fall back to `_default`.
   - **When you're in it** and **Next up:** copy.
   - **For you:** copy keyed by `outcome`.
4. **Join Snooze:** price in the display currency (`snooze_currency_preference`, else the locale rule from the existing quiz: AU → aud, otherwise usd), the guarantee line, and the primary CTA going to the offers.json checkout URL. UTM params are appended from current-touch storage. The link carries `data-offer="snooze"` so the existing currency toggle keeps working.
5. **What happens after you join:** a numbered list from `plan.next_steps.snooze[]`.
6. **Want more hands-on support?** Camp and consult cards (`plan.cards.camp.*`, `plan.cards.consult.*`, each with its own `next_steps[]`). The highlighted card follows `highlight_by_help_style`: it is expanded and badged `plan.recommended_badge`. The others are collapsed (`<details>`).
7. **Safety route** (any red flag in `safety`): `plan.safety.note.<flag>` is shown first, for each flag chosen. The consult card is highlighted and appears before Snooze. The **Right now** section is suppressed. For `parent_struggling`, `plan.safety.support_lines` (PANDA / PSI / emergency) is shown.

## Site-wide state (`get-started-state.js`)

- Runs on every page (a global header paste). It reads the same storage key with try/catch.
- For each `[data-get-started-cta]`:
  - no state → label `data-label-start` (default "Get started"), href `/get-started`
  - in progress → "Continue where you left off"
  - email captured or completed → "See your plan"
- The labels come from the element's `data-label-*` attributes if present, otherwise from built-in defaults. On load the script stores the original label and href as `data-fallback-label` and `data-fallback-href`.
- **Welcome-back bar:** if the visitor is in progress or completed and not on `/get-started`, show a slim dismissible bar: "{welcome_back}" plus a link. It is dismissed per session through sessionStorage.
- **Kill switch:** `window.SNOOZE_GET_STARTED_ENABLED === false` puts the fallbacks back and shows no bar.

## Copy keys (`copy.json`)

Nested object. Required top-level keys:

- `welcome{eyebrow,title,body,credential,cta}`
- `resume{title,body,continue,restart}`
- `screens.<screen_id>{title,helper}` for every non-intro screen
- `options.<screen_id>.<option_id>` (the label) for every option, including age bands, `extra_toggle.multiples`, every struggle across all groups, outcomes, help styles and safety options
- `empathy{title,body,cta}`
- `building{title,items[]}`
- `email{title,body,privacy,fallback,skip}`
- `plan{header,prepared_by,photo_url,reflection.<group>,reflection_struggle.<struggle>,right_now_title,in_the_moment{title,body},next_up{title,body.<group>},for_you.<outcome>,join{title,price_suffix,guarantee,cta},next_steps{title,snooze[]},more_support_title,recommended_badge,cards{camp{title,body,cta,url_key,next_steps[]},consult{...}},safety{title,note.<flag>,support_lines[]}}`
- `state{start,continue,see_plan,welcome_back,welcome_back_link}`
- `common{continue,back,step_of}`

`lint-flow.mjs` fails on any missing key or any leftover `{{`.
